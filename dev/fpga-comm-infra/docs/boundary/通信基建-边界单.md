## 1. 一句话目标

完成通信基建第一步两项硬约束：① TCP 网络帧 **payload 提取**（64b AXIS 入/出）；② FPGA 产物 **UDP 组播出**（单包 <512B）。本步只建「能进能出」的通信底座，不扩产品功能。

---

## 2. 实施优先级（组长已裁）

**先 ② UDP 组播 TX，再 ① TCP payload strip。**

理由：② 依赖少，可先冒烟「FPGA 产物能出网」；① 依赖入侧语义，现已钉死 H4，但仍比 ② 重。

---

## 3. 硬约束（In Scope）

1. **TCP 帧 payload 提取**
   - 入/出接口：64-bit AXIS
   - 对齐调研选项 **A**：仅 strip 头，输出 payload 流（不做轻量 TOE，不做主机栈 + Delegated Send）
   - **H4（已裁定）：** 入侧为「带 L2–L4 的网络帧/包」；出侧为纯 TCP payload。若实际是 segment 流，走变更流程，不得默改。
2. **FPGA 产物 UDP 组播输出**
   - 单包长度 **<512B**（口上须可拦超长）
   - 对齐调研选项 **A/B 的 TX-only**：硬核模板头组播 TX，或通用 UDP/IP + RFC1112 MAC 映射旁路 ARP；**IGMP / RX 不进本步**（见 H3）

---

## 4. 明确不做（Out of Scope）

- 完整 TCP 状态机 / 乱序重传 / 握手重建
- 策略、订单簿、行情解析等业务扩 scope
- UDP 组播收端、IGMP join
- 对组播组地址做 ARP（禁；与仓内已有 FROZEN 组播 TX 惯例一致）
- 与 UDP 热路径抢同一出口且未分角色的混用（本单只定边界，架构归设计侧 D1–D4）
- 将组播组地址 / 端口写死进 RTL（必须经 meta/CSR 参数化，见 H1）

---

## 5. 验收口径（组长裁剪后照收）

### 5.1 ② UDP 组播 TX（优先）

对齐 A/B TX-only，单包 <512B：

- 单包长度口上拦死 **<512B**；超长不发或显式丢 + 可观测
- IP DA ∈ 224/4；Eth DA 按 RFC 1112；**永不对组地址 ARP**
- TTL 按本边界单（**H2 = 1**）；TX-only，无 IGMP / RX（**H3**）
- 用户侧 AXIS payload + meta（组/端口，**H1 参数化**）与 MAC 口角色分离

### 5.2 ① TCP payload strip

对齐选项 A；入侧语义见已裁定 H4：

- 入/出均为 64b AXIS；正确处理 `tkeep` / `tlast`
- 出侧仅为 TCP payload，**无 L2–L4 头**；字节对齐正确（含 TCP options 变长）
- 反压时不丢边界、不假造 `tlast`
- **明确不测：** 握手 / 重传 / 乱序重建、完整状态机

## 7. 调研素材与附录

调研专员交付（2026-09-09）；事实与选项，**不落架构**。

### 7.1 TCP 帧 payload 提取（64b AXIS，对齐选项 A / H4）

**惯例：** 金融场景里 TCP 多承担会话/补包/控制（如 CME MDP TCP Recovery），热路径行情常走 UDP。硬件侧常见做法是 partial offload：只剥头吐纯 payload，不做完整 TCP 状态机。10G 公开例见应用口 AXIS、数据通路 64b（MDPI Sensors 2023, Low Latency TOE…）。

**注意：** 入侧按边界单为带 L2–L4 的帧/包，出侧仅 TCP payload；64b 必须正确处理 `tkeep`/`tlast`；TCP options 使头长可变，payload 起点按 IHL 字节对齐，禁止固定偏移假设。

**坑：** 把 strip 扩成握手/重传/乱序重建；反压时丢包界或假造 `tlast`；与 UDP 出站口角色混用。本步明确不验收完整栈。

**出处：** CME MDP Dissemination / TCP Recovery（cmegroupclientsite wiki）；MDPI Sensors 2023 10G TOE（https://www.mdpi.com/1424-8220/23/10/4690）。

### 7.2 UDP 组播 TX（TX-only，单包 <512B）

**惯例：** 产品/事件出站用 UDP 组播；<512B 通常不分片，约束的是线速发包率与口上长度门。开源栈常需旁路单播 ARP 才能发组播（alexforencich verilog-ethernet）。

**注意：** IP DA∈`224.0.0.0/4`，SA=接口单播；Eth DA=`01:00:5e` + 组地址低 23 bit（RFC 1112）；TTL 显式（本步已裁定默认 1）；用户 AXIS payload+meta（组/端口参数化）与 MAC 口分离；校验和伪首部目的地址用组地址。

**坑：** 对组地址做 ARP / 走 `udp_complete` 等 ARP 路径导致发不出去；只改 IP 不改 MAC；TTL 过大窜出二层域；超长包未在口上拦；TX-only 却依赖 IGMP join（收是另项）。

**出处：** RFC 1112；alexforencich/verilog-ethernet#11、PR#18；仓内既有 FROZEN 组播 TX 方案可作同向参考（不替代本边界单）。
