# 专业团队职责章程（设计层）

日期：2026-09-08  
状态：**生效**  
范围：组内只做 FPGA **设计层**；编码与仿真交给下游。

---

## 1. 使命

对齐上层业务需求后，输出可交给下游开工的：

1. **架构方案**（层次 / 时钟域 / 延迟·吞吐预算 / 与周边模块咬合）  
2. **完善设计方案**（接口契约、参数归属、处理序、失败模式、复用边界）  
3. **验证方案**（验收点与覆盖意图；**不写** TB / 不跑仿真）

下游据此编码、仿真；本组不落 RTL、不改仿真环境（除非用户显式改范围）。

---

## 2. 固定交付包（缺一不冻）

| # | 交付物 | 最低内容 |
|---|---|---|
| D1 | 架构总稿 | 模块树、钟/复位、数据面/控制面、延迟可加算、与业务/DMA/线侧咬合 |
| D2 | 接口契约 | 口形（AXIS 等）、CSR / meta / 核内派生三分法、反压角色、默认参数 |
| D3 | 验证方案 | 「查什么」表：合法/非法/默认值/反压/不回灌；明确本轮不做的项 |
| D4 | 风险与假设 | 机房/线速/同卡 RX 等未定项；缺页清单（如 `ip-catalog`、异钟 afifo） |

**冻结**：组长在四样齐全后宣布 FROZEN；此后改语义走**变更单**，禁止静默改契约。

---

## 3. 三道门禁

| 门 | 谁 | 过门条件 |
|---|---|---|
| G0 业务 | 上层 / 产品 | 「传什么」签字（组地址、TTL 策略、是否上某业务流等） |
| G1 设计 | **本组长** | D1–D4 齐 → FROZEN |
| G2 下游复审 | 编码/仿真方 | 对照契约实现；发现契约冲突 → 打回或变更单，**不得**私改冻结语义后合入 |

---

## 4. 角色与分工

| 角色 | 设计轮职责 | 不做 |
|---|---|---|
| **组长** | 分工、争议拍板、收总稿、宣布 FROZEN、卡 G2 变更 | 代写全量切片、代下游写码 |
| **架构 / 方案主笔** | D1 主笔；咬合与延迟数字；**唯一总稿收口人**（可与组长同一人） | 多份并行「准冻结」 |
| **接口协议** | D2：口表、反压角色、字段归属、禁 ARP/禁用户 MAC 等铁律 | 业务内容定义 |
| **并行 / 数据面** | 扇出、流水线、多客户抢口、背压不回灌铁律 | 协议字段咬文嚼字 |
| **模块 / IP 复用** | 内联 vs catalog；开写前缺页清单；异钟才 afifo | 无页手写 CDC/FIFO |
| **验证（设计态）** | D3 验收点 / 覆盖意图 | TB、`make sim-*`、覆盖率收数 |
| **可实现性 / 家规**（原代码评审·设计态） | 命名/复位/三段式等开写前约束 | 合入前 RTL PR 深审（归下游或兼职） |

**按需、非常驻：** 器件/板级/时序、纯业务产品、RTL 实现（顶级码农/云端）。

---

## 5. 与上下游接口

**上游输入（最低）：** 业务目标、关键参数或「由 FPGA 建议默认」、约束（延迟/带宽/是否 TX-only）。  
**下游输入（开工包）：** FROZEN 的 D1–D4 路径 + 变更记录。  
**下游输出（回组）：** 路径清单、回归命令与结果；契约偏差报告（若有）。

---

## 6. 工作节奏（建议）

1. 业务对齐（G0）→ 假设表进 D4  
2. 各角色出切片 → 架构主笔收 D1/D2 → 验证出 D3  
3. 组长评审纪要 → **FROZEN（G1）**  
4. 移交下游 → 复审门禁（G2）→ 实现 / 仿真  
5. 仅当 G2 打回或变更单时重开设计轮  

---

## 7. 铁律（从既有项目沉淀）

- 设计轮：**不编码、不跑 TB**（用户另有指示除外）  
- 验证止于方案；仿真属下游  
- 开写前须有 `ip-catalog` 骨架（或 D4 写明例外）  
- 反压角色、默认参数、失败模式必须写进契约，供 TB 对照  
- 冻结后改语义 = 变更，不是「实现细节」

## 8. 稀有异常铁律（2026-09 增补）

**默认交付：** 门禁/一致性失败 → **丢 + sticky/计数可观测** → **`sys_rst_n` 空管回 IDLE**。

**反对：** 为低频「万一」堆恢复态、影子机、旁路自愈通路。

**放行加复杂恢复的条件（须同时）：** ① 业务证明会高频发生；② 复位清空不够用。否则 D3 对该类恢复标 **N/A**；要加测走变更单。
