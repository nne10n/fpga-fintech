## 1) 本轮调研方向清单（5 条）

| # | 方向 | 服务什么 |
|---|---|---|
| D1 | L2 聚合档在片外存储器上的惯例与语义 | H2 验收：何谓「全量档位」、空档/Σqty=0 |
| D2 | DDR 权威下片上 Top-10 投影与修补 | H3 验收：插入/撤销/成交后十档如何保持一致 |

## 2) 分方向 DeepSeek 提示词

### 提示词 D1 — L2 聚合档（DDR 全量）

```
你是金融行情/FPGA 资料凝练助手。只输出「惯例 / 注意 / 坑 / 出处」四段短文，可附选项表。禁止：RTL、模块划分、策略/报单、编造延迟数字、推翻下列已裁定。

【已裁定】硬件行情订单簿：DDR 存的是 L2 聚合档（每个价位 Σqty / 可选 order count），不是 L3 逐单链表；最大 4096 标的；片上另有买卖各 10 档（本条不展开十档）。

【输入范围】公开厂商产品说明、专利摘要、学术论文（如 He FPL 2017、Liu ASAP 2024）、开源订单簿 README；优先一手 URL。无出处的断言标「未核实」。

【请凝练】
1. 惯例：生产/论文里「全量 L2 档」通常存什么字段；固定 tick 数组 vs 稀疏价哈希聚合的适用市场。
2. 注意：空档删除 vs 留零、跨 tick 改价、同一价多笔合并为档的语义。
3. 坑：把 L3 当成 L2、BRAM 硬塞全市场、用未核实 ns 当指标。
4. 选项表（2–4 行）：仅关于「DDR 内 L2 记录内容/索引方式」的业务选项，不写电路。
5. 出处：标题+年份+URL（≥3）。
```

### 提示词 D2 — Top-10 投影修补

```
你是金融行情/FPGA 资料凝练助手。只输出「惯例 / 注意 / 坑 / 出处」与一张「事件→十档影响」选项/规则表。禁止：RTL、策略、写死延迟 ns、推翻已裁定。

【已裁定】DDR 为 L2 全量权威；片上维护买卖各 10 个聚合价位，是投影并需修补；不是十笔最优订单。

【输入范围】Top-N cache / L2 depth=10 的论文与产品（He Top-5 cache、Algo-Logic 默认 10 档、LightTrader 10 档、Exegy 可配 top N 等）；说明证据等级（论文/厂商/教学）。

【请凝练】
1. 惯例：为何热路径用片上 Top-N 而非每次扫全深。
2. 注意：优于第 10 的新档插入、撤销第 k 档、档量变 0、买/卖侧独立时的一致性。
3. 坑：片上已变 DDR 未写回导致语义分叉；每笔重排全 DDR；空档/涨跌停未定义。
4. 表：至少覆盖 加档 / 撤档 / 量变 / 触及第 10 档外 四类，每类给出「可验收的对外行为」文字（非电路）。
5. 出处 ≥3，带 URL。
```

### 提示词 D3 — 4096 固定槽与超限

```
你是金融行情资料凝练助手。围绕「固定 N 槽标的表、超限拒收可观测」输出惯例/注意/坑/出处+选项。禁止架构/RTL/策略；禁止编造容量 benchmark。

【已裁定】固定 4096 槽；超限必须拒收且可观测；不在本步做动态扩表。

【输入范围】厂商公开的品种容量口径（如 nxFeed / nxAccess / NovaSparks 历史稿中的 instruments 数）、教学/开源里固定槽或哈希上限做法；容量数字必须带来源，并标明厂商宣传 vs 论文。

【请凝练】
1. 惯例：固定槽 vs 稀疏哈希在「上限几千标的」时的取舍（业务语言）。
2. 注意：slot 分配/释放、重复订阅同一标的、超限时入事件如何拒绝。
3. 坑：静默丢弃超限；把 4096 当成必须全进 BRAM。
4. 选项：可观测手段（计数器/状态位/事件码）列 2–3 种业务级选项，不写寄存器图。
5. 出处 ≥3。
```

### 提示词 D4 — 协议无关簿内核

```
你是金融行情资料凝练助手。目标：界定「簿内核」最小输入事件集，使内核协议无关、具体 feed 适配后置。禁止写死某一交易所二进制格式；禁止 RTL；禁止策略。

【已裁定】H1：簿内核协议无关；ITCH/某所适配后置。

【输入范围】归一化 book 事件常见分类（add/cancel/modify/trade/或档级 update）；Exegy ONPA 等公开叙述中的 order vs price 流（仅作参考）；A 股档级快照+逐笔与 ITCH 增量的差异（业务层）。

【请凝练】
1. 惯例：协议无关内核通常吃哪些「规范化事件」（用业务名，不写报文 layout）。
2. 注意：order-based 市场 vs book-based 档更新如何都映射到「L2 聚合档变更」而不污染内核。
3. 坑：在内核里写死 Stock Locate / 某所字段；把会话/回放当内核职责（本步 H5 已排除恢复）。
4. 选项表：2–3 种「适配层→内核」事件粒度（例如：逐单再聚合 vs 直接档增量），供边界附录，不选架构。
5. 出处 ≥3。
```

### 提示词 D5 — 标脏且无缺口恢复

```
你是金融行情资料凝练助手。本步明确不做缺口恢复/TCP 重传/snapshot 灌簿；仅允许标脏。输出惯例/注意/坑/出处。禁止设计恢复状态机；禁止策略。

【已裁定】H5：本步不做缺口恢复，可标脏。

【输入范围】生产侧常见「FPGA 热路径标脏 + CPU 恢复」分工（nxFeed resync、NovaTick late join 等公开叙述）；CME 等「双 feed 仲裁仍可能双丢」的业务事实（只到「需要恢复」一层，不写本步实现）。

【请凝练】
1. 惯例：何种条件应标脏（序号缺口、校验失败、内部溢出、超限拒收是否算脏等——给出选项不要替业务拍板）。
2. 注意：脏后对外输出是否静默/打标记/停更新；与「十档仍可能旧」的风险。
3. 坑：把标脏当成已恢复；本步偷偷做 IGMP/TCP 补包。
4. 短选项表：脏后对外行为 2–3 种，供验收选用。
5. 出处 ≥2。
```
