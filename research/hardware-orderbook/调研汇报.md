# FPGA 硬件行情订单簿：产品与核心设计思路

资料截止：2026-08  
汇报口径：只写可对上公开一手来源的事实。数字分三类标注：**【STAC】** 独立基准；**【厂商】** 厂商规格或宣传，未经第三方审计；**【论文】** 学术研究。厂商数不写成已审计结论。

---

## 一、结论与范围

**一句话：** 2026 年能指着产品页说「FPGA 上建簿」的，主要是 Exegy 家族（nxFeed / nxAccess / XTP / Nexus，以及 2026-01 并入的 NovaTick）。Celoxica QDS 有 full depth 功能，公开证据薄。Algo-Logic 有过 L3 IP，公开材料停在上一代。中国厂商公开页几乎是 FPGA 解码或组播，建簿写在「软硬融合」表述或恒生 2026 专利里，不要和 nxFeed 级 ticker plant 画等号。

**先钉死什么不是订单簿。** STAC-T0 规格写明 SUT 不做交易逻辑、不做市场协议。**【STAC】** 13.9 ns 是 UL3524 + nxTCP-UDP 的 actionable I/O，是网卡反应，不是簿。下列对象同样不是订单簿产品：L1 交换机、硬件 TCP、Nasdaq FPGA 行情通道（payload 与软件版相同，只是未整形分发）、Alveo UL3524 卡本身。

本稿只谈「硬件上如何维护可查询的价格档 / 订单视图」，不把解码、组播、发单、风控混进建簿能力。

---

## 二、产品格局

能公开指认「FPGA 建簿」的，按证据厚度排如下。延迟数字凡未标 STAC 的，均为厂商规格或会议幻灯，且多数幻灯本身注明 Not STAC。

### 1. Exegy 家族（当前最完整）

**nxFeed（原 Enyx）。** FPGA NIC 上做仲裁、解码、归一、建簿，同时提供 book-based 和 order-based 视图。**【厂商】** 2025-03 事实表：avg **<1.2 μs**、max **<8 μs**，SOP-to-SOP on switch，非 STAC。2021 brochure 更激进（avg **<1.0 μs** / max **<4 μs**），引用必须带版本，不能把 2021 最小数字当成 2026 现状。容量 **16–250k** 品种/卡。交给软件的路径：PCIe C++ API，或最多 8 路 UDP multicast。

**nxAccess。** 片上 feedhandler 建簿；另有 pattern matcher，可以绕过建簿直接触发。**【厂商】** CME tick-to-trade（含执行，不是纯建簿）：有 pattern matcher **389 ns** / 无 matcher **624 ns** / 软件路径 **1.5 μs**。最多 **8000** symbols。同一 FPGA 既建簿又执行，所以建簿路径容量远小于 nxFeed。

**Nexus（计划 2025 Q4 美股）。** 一体机内做 feed、book building、arbitration；Smart NIC 把簿聚合并 DMA 进应用内存。**【厂商】** 2026-04 事实表：**<2.0 μs** UBBO-triggered trade，**<270 ns** raw signal（这是触发口径，不是全深建簿延迟）。最多 8 张 FPGA；行情侧 AMD X3，执行侧 Bittware XUV-V8。

**XTP。** 提供 BBO 与 full-depth，以及 UBBO / Virtual Order Book。**【厂商】** 产品单 2023-08：load 下 low microsecond。交付 RDMA 或 TCP。架构细节主要在专利，不在产品页。

**NovaTick（NovaSparks，2026-01-14 被 Exegy 收购）。** 纯 FPGA 建簿，可选 L1 / L2 Top-N / L3 full depth。CPU 只做 recovery。**【会议幻灯，非 STAC】** 2016 STAC Summit：Nasdaq ITCH 全市场 Ethernet **800 ns** / NovaLink **750 ns** / PCIe DMA **1250 ns**。收购后官网大量 404，这组数字偏旧，只能当历史锚点，不能当 2026 产品规格。

### 2. 其他海外产品

**Celoxica QDS。** 产品页写 full depth order book(s)，覆盖 **80+** 场所，C++ API + DMA。当前页没有纳秒级建簿数字。有功能，证据薄。

**Algo-Logic Full Order-Book。** L3 逐单，默认 10 档 L2。**【会议幻灯，非 STAC】** 2013：L3 **<450 ns**。材料停在上一代，不宜写成现行可采购栈。

### 3. 国内：解码已落地，建簿多数未钉死在 FPGA

**华锐 D1。** 沪深 L2 硬解。**【厂商/实验室】** 解码深市 **130 ns**、沪市 **210 ns**。解码不等于建簿。公开表述有「软硬融合…实时订单簿构建」，未单独证实簿维护发生在 FPGA 内。

**恒生。** 公开产品是 FPGA 解码。**【公开稿】** 全链路解码约 **1.3 μs**。FPGA 缓存内建簿，出现在 2026-02-17 授权专利 CN202511374997.1，不是已上架产品页。

**盛立 EFH。** 已发布 FPGA 解码。DolphinDB 的 tree / 建树是行情数据类型，不能据此认定为已证实的 FPGA LOB 引擎。

**不做簿，或公开材料未证实簿在 FPGA：** LDA、Accolade、Cisco/Exablaze FDK、宽拓、华云 HQM（615 ns 是穿透解码）。

## 三、核心设计思路

### 1. 流水线骨架

硬件建簿不是「把软件 LOB 搬进 FPGA」，而是一条必须摊平最长路径的流水线：

解析 → 品种哈希映射 → 用 order-id 找回订单 → 更新价格档 → 更新 BBO / Top-N → 发增量或快照。

Exegy 专利 US12211101B2（2025-01-28）把这条链写清楚了：FPGA FAM 上 Parse → Symbol Map → ONPA（归一 + 价格聚合）→ 过滤 → SVU（排序视图）→ Format。这是目前能对上产品家族的最完整公开架构。

进簿之前还有几步取舍。nxFeed / nxAccess 做逐消息 A/B 仲裁。NovaTick 把交易所 recovery 放在 CPU，FPGA 不跑完整重传。价格打成 64-bit 定点数。nxAccess 可以关掉价格 / 品种归一，用功能换纳秒。

### 2. 两派数据结构，对应两套市场规则

**ITCH / 全球市场（价格近乎无界）。** 订单用 order-id 找回：H3 哈希 + chaining。价格档另做 `(symbol, exchange, price)` 哈希聚合。排序不用 AVL：要么锚定数组加 memmove，要么 B+ 树（叶链表方便出 snapshot）。

**A 股 / 中金所（涨跌停、固定 tick）。** 价格是有界网格，可以直接当地址。He 等（FPL 2017）**【论文】**：`addr = base + (p − p_ld) / tick`，加撤就是加减计数，不维护每笔链表。Liu 等（ASAP 2024）**【论文】**：价位直接映射 DRAM 地址，两级 cache 管 BBO 和快照；摘要给出 **26–209 ns**、**>3.26 Mmsg/s**。全文未拿到，这组数字以摘要为准。

延迟的本质是摊平最长路径。He 证明：无 cache 时 Publish = **5 log n**，会卡住流水线；Top-5 cache 之后 Publish 回到 **O(1)**。FPGA2（2017，中金所）**【论文】**：Add **288 ns** / Publish **132 ns**。

### 3. 存储分层，决定容量和延迟

BRAM 放热数据 / TOB；片外 DRAM 放全深；主机只接 stream view 或 L2 snapshot（Nexus DMA，历史上还有 CAPI 128B）。这解释了两张产品规格为什么差一个数量级：nxFeed **16–250k** 品种，是因为 by-price 不存每笔；nxAccess 建簿路径只有 **8k**，因为同一块 FPGA 还要执行。

### 4. 双路径，而不是「簿越全越好」

nxAccess 同时提供完整建簿和 pattern matcher（可绕过建簿）。NovaTick 可选 L1 / L2 / L3。NovaSparks 2021 的 consolidator 是第二级 FPGA，用来并 NBBO，不是把微观结构因子做进第一级。公开材料没有把 imbalance / microprice 写成 FPGA 模块。监管要 L3，HFT 往往只要 BBO 加几档，产品用可选深度把这条张力暴露给客户，而不是做成单一全深引擎。

## 四、设计张力与国内情况

张力是工程选择题，不是路线对错。

| 张力 | 含义 |
| --- | --- |
| 全深 vs 延迟 | 全市场 L3 吃片上内存和最长路径；HFT 常用 BBO + Top-N |
| 多市场合成 | 往往是第二级 FPGA 再并簿（NovaSparks consolidator），不是第一级 feedhandler 顺手完成 |
| 24×5 与晚加入 | 完整 snapshot / recovery 仍在 CPU；FPGA 不负责把晚加入会话从零重建 |
| 馈源速率 | 25G / 100G 下，建簿比 MAC 先饱和 |
| 缺口恢复 | 公开设计不把完整重传放进 FPGA |
| 监管 vs 交易 | 监管要 L3 审计轨迹；交易只要能触发的那几档 |

国内公开材料的位置，和海外 ticker plant 不在同一层。华锐、恒生、盛立能被核实的，主要是 FPGA 解码（以及组播分发）。「实时订单簿」出现在软硬融合表述或专利权利要求里：恒生 2026 专利写了 FPGA 缓存内建簿，华锐未单独证实簿在 FPGA。把国内「硬解 + 主机建簿」画成 nxFeed 同级，证据不够。

学术 2023–2026 不能当产品。Liu 等 ASAP 2024 是最直接的建簿论文。LightTrader（HPCA 2023）是把本地少数档送给 AI，不是 ticker plant。He 2017 仍被引用，说明价格网格这套 A 股/中金所打法没有被取代。AXOrderBook 是 A 股 HLS 实验；SEO 转载的 150–200 ns 弃用。

## 五、证据边界与判断

**没有公开 STAC 测的是「FPGA 建簿」。** STAC-T0 测的是网卡 I/O。NovaSparks 2016、Algo-Logic 2013 的幻灯都写明 Not STAC。nxFeed / Nexus / nxAccess 的微秒、纳秒数字是厂商事实表或产品页。

**规格会变严，不要取历史最小值。** nxFeed 2021 比 2025-03 更激进；NovaTick 官网收购后大量 404，2016 数字只能当史。Celoxica 有功能无 ns。Algo-Logic 停在上一代。

**国内建簿未钉死在 FPGA。** 华锐实验室 130 / 210 ns、华云 615 ns、恒生公开稿 1.3 μs，能对上的是解码或穿透，不是簿。Liu 全文未拿到，26–209 ns 来自摘要。

**判断：** 若汇报对象问「现在买谁的 FPGA 建簿」，公开可指认的仍是 Exegy 家族，Nexus 是一体机方向，NovaTick 是被并入的纯 FPGA 建簿血统。若问「13.9 ns 能不能代表建簿」，答案是否定的。若问「国内有没有对等产品」，公开证据只支撑到硬解，建簿仍是软硬融合或专利表述。
