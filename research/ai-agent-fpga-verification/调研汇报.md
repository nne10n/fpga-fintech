# AI Agent 在 FPGA 开发与验证中的成熟流程、做法与 Skill

资料截止：2026-08  
汇报口径：只写可对上公开一手来源的事实。厂商加速倍数（常见 50× / 40× / 10× 一类表述）一律按**新闻稿或 EA** 标注，不作为排期或产能假设。VerilogEval 分数是基准集成绩，**不得外推**到生产交易 IP。名称以厂商现行产品为准：SimAI 属于 Cadence Verisium；新思是 Synopsys.ai Copilot 与 AgentEngineer™；Intel Quartus **没有**官方 AI assistant。文中不使用「Questa One SimAI」「Synopsys AgentAR」这类不存在的名称。

---

## 一、结论与成熟度地图

**一句话：** 2026 年可复制的是闭环模式，不是端到端自治签核。成熟做法是：人持有 golden 与 spec，agent 写 RTL，Verilator + cocotb 仿真，解析日志再打补丁。主风险不是「综合不过」，而是**综合过但算错**（FinHardBench 功能正确率 19–61%）。

可落地的判断标准不是「agent 会不会写 Verilog」，而是「错误会不会在 bitstream 之前被冻结的 checker 抓住」。把 VerilogEval 高分当成交易 IP 可签核，是口径错误。

### 成熟度地图

| 阶段 | 成熟度 | 可复制的内容 |
| --- | --- | --- |
| 写 RTL → 仿真 → 解析日志 → 补丁 | **相对成熟，可抄** | AutoChip、AIvril、VerilogCoder。栈优先 Verilator + cocotb / pytest，不要一上来 SV / UVM |
| 形式化辅助写 SVA | **相对成熟，但必须人审** | AssertLLM / AutoSVA2；人审后再 FPV。厂商侧有 Synopsys Formal Advisor、Cadence ChipStack 的 Jasper skill |
| FPGA 工具驾驶（读文档、跑流程、看报告） | **新兴，早期可装** | AMD Vivado / Vitis AI Assistant + 文档 MCP；oh-my-fpga 的 named skills；SynthPilot 驱 Vivado / Quartus / 安路 |
| 生产交易 IP：RTL → bitstream 全自治 | **不成熟** | 禁止作为目标。FinHardBench 说明能综合 ≠ 算对 |
| 相信 LLM 完成时序收敛 | **不成熟** | AMD 与 oh-my-fpga 都要求 post-impl 证据。Vivado RQA / RQS / IDR 仍是引擎，agent 最多建议 XDC |
| 一次性生成可跑的 SV / UVM | **不成熟** | GoGoTB 复现 UVM²：8 个设计上环境成功率 0%；Python TB 才跑通 |

## 二、可抄的闭环做法

公开材料里真正被多次复现的，不是「一个 agent 从 spec 签到 bitstream」，而是一条短闭环：

1. 人给出 spec 与冻结的 golden（Python 或 C），禁止同一模型同时写 RTL 和 checker。
2. Agent 写 RTL。
3. Verilator lint，再 pytest-cocotb 对 golden。
4. 失败时只把**精简日志**喂回去打补丁（AutoChip：succinct 反馈优于全历史；arXiv:2311.04887）。
5. Testbench 冻结（AIvril 的做法）：agent 不能改 checker 来「让它过」。
6. 迭代次数设硬顶（实践上 n≤5），覆盖下降则 rollback。

VerilogCoder（AAAI 2025）作者报 VerilogEval-Human v2 **94.2%**。这是基准成绩，只说明「在 VerilogEval 上、在该论文设定下」写 RTL 的命中率，不能写成生产交易 IP 的签核概率。

形式化走另一条短链，不要和仿真闭环搅在一起：agent 从 spec 起草 SVA → 人审 → 对协议 / CSR 做有界 FPV。AssertLLM、AutoSVA2 是这条链的学术原型；厂商对应物是 Formal Advisor 和 Jasper skill。SVA 不经人审直接当 sign-off，与「综合过但算错」是同一类风险。

仿真器选择不要为 AI 而换。cocotb 可以挂 Questa，也可以挂 VCS。跟能拿到 EA 的厂商走即可：Siemens Questa One Agentic Toolkit 已在 2026-02 出 EA；Synopsys 长跑 DV agent 计划 2026 下半年供货（新闻稿，不是已排期承诺）。

## 三、厂商 2024–2026

### AMD

路径是「文档 + IDE agent + 实现后证据」，不是替换 Vivado 引擎。

- Vitis Unified IDE 提供 AI Assistance（UG1400，2026-07-31；UG1702 加速参考里的 AI Features）。
- 文档侧有 vivado-doc-server MCP，把 UG 接到 agent。
- 可与 GitHub Copilot 联用；Horizons 2026-05 有工作坊。
- 时序、CDC、实现质量仍以 post-impl 报告为准。RQA / RQS / IDR 是工具引擎，不是 LLM。

Quartus 没有对等的官方 AI assistant。不要把 AMD 这条写成「FPGA 厂商标配」。

### Siemens（Questa One）

- 2025-05-13 发布 Questa One：RTL、Lint、CDC、验证规划、Debug 五个 agent，定位是补验证产能缺口（新闻稿）。
- 2026-02-27 Questa One Agentic Toolkit 进入 **EA**；经 MCP 接 Copilot / Claude / Cursor。
- SimAI 不是 Questa 产品。Cadence Verisium SimAI 是另一条线，从 2022 年起做 ML 回归和覆盖，不是 LLM agent。

### Synopsys

- 现行名称：Synopsys.ai Copilot（Code / Formal / Lint Advisor）与 AgentEngineer™。不存在「AgentAR」产品（那是 UIST 2025 的 AR 论文）。
- AgentEngineer Converge 在 2026 宣传 L4。DAC 2026-07-26 展示长跑 DV agent，新闻稿写 2026 下半年供货。这是供货意向，不是项目排期。
- 与 AMD、Microsoft Discovery 有联合评测，公开材料不足以当成生产交易 IP 的签核案例。

### Cadence

- Verisium：2022 年起的验证数据平台，ML 做回归与覆盖，不是 LLM 写 RTL。
- 2025-11 收购 ChipStack，2026-02-10 发布 ChipStack AI Super-Agent：前端 agent + Jasper。这是 Cadence 把 agent 接到形式化的主产品，不是 Questa。

厂商新闻稿里的 50× / 40× / 10× 一类加速，一律视为营销或 EA 环境数字。汇报里可以转述来源，不能据此压缩项目周数。

## 四、学术与开源框架

### 通用 RTL 生成（背景，不是 2026 主线）

ChipNeMo、RTLCoder（GitHub 约 310★）、ChatEDA、HDLAgent（已 archive）证明「能写 HDL」，没有证明「能签核」。RTLCoder 仍是最常见的开源参照，但不要当成验证闭环。

### 验证闭环（2025–2026，应单独看）

这一波论文的共同点：失败发生在**环境能不能跑起来**，其次才是功能覆盖。

| 工作 | 做法 | 公开结果（作者报） | 对工程的含义 |
| --- | --- | --- | --- |
| UVLLM / UVM² / UVMarvel | 往 UVM 上堆 LLM | GoGoTB 复现 UVM²：8 个设计环境成功率 **0%** | 不要把「生成 UVM」当第一步 |
| HAVEN | LLM 只做规划，模板出 UVM | 把生成范围从代码收到规划 | 人控模板，比让模型写环境更稳 |
| GoGoTB（2026-07 预印本） | cocotb + Verilator，spec 锚定覆盖 | 8 个设计环境成功 **100%**，功能覆盖均 **83.2%** | 与第二节可抄闭环一致 |
| AgentDV（2026-08 预印本） | CSR / RAL 接地，OpenTitan | 无框架时单次 Claude 覆盖环境 **0%**；AES 数据通路 line 约 **37%** | 没有接地的 RAL，agent 会空转 |
| LLM4DV（FCCM 2025） | 覆盖驱动激励 | 适合夜间跑完后补残差 bin | 放在已有仿真器之后，不要替换仿真器 |

### FPGA 会议与 HLS

- LLM4DV（FCCM 2025）：覆盖驱动激励，是验证侧最接近 FPGA 会议的工作。
- HLS-Eval / ChatHLS / FPGAgent：HLS 到板级。CSIM 过、综合过，都不等于上板可跑。HLS 路径必须把 COSIM 和上板写成独立门，不能并进「编译成功」。

FinHardBench（2026-08）把风险写死了：LLM 写金融 Verilog，功能正确率 **19–61%**，能综合但算错很常见。这是把 agent 用于交易 IP 时的主证据，优先于任何 VerilogEval 分数。

## 五、Skill / MCP 清单

下列是 2026 年公开可装、可写进仓库的能力单元。星数低（公开可见约 0–109），视为早期，不是生态成熟度证明。

### 本周可直接写入仓库的六条

| Skill | 作用 | 硬约束 |
| --- | --- | --- |
| `verilator-loop` | lint → 仿真 → 精简日志 → 补丁，n≤5 | 只改 RTL，不改 checker |
| `golden-gate` | golden.py / C 由人持有并冻结 | 同一模型不得同时写 RTL 和 checker |
| `coverage-gap` | 覆盖下降则 rollback；残差 bin 定向补测 | 补测不能降低已有覆盖 |
| `xdc-first` | 时序问题先改约束和策略 | 禁止把 LLM 口头「已收敛」当证据 |
| `cdc-never-waive` | agent 可读 CDC 报告、建议约束 | **禁止自动 waiver** |
| `no-bitstream-on-compile` | 综合成功不得出 bitstream | 见第六节门禁 |

### 可叠加的现成包

- **oh-my-fpga**（GitHub: LNC0831/oh-my-fpga）：13 个 named skills，覆盖 timing-closure、cdc-audit、full-flow-demo、sim-bringup、coverage-closure、ila-hw-debug、zynq-bringup 等。与上表六条互补：上表管纪律，oh-my-fpga 管 Vivado 流程动作。
- **AMD vivado-doc-server MCP**：把 UG 接到 agent，减少过时 Tcl 幻觉。文档搜索已进入 2026.1；执行层 EA / GA 边界在公开文档里不完全清楚。
- **SynthPilot MCP**：驱动 Vivado / Quartus / 安路。中文站；zip 安装包在 2026-03 停更。官网「900+ 工程师」是宣传语。有则叠加 oh-my-fpga，没有则不要为它改工具链。
- **Siemens Questa One Agentic Toolkit MCP**：接 Copilot / Claude / Cursor。2026-02 EA。
- **Cadence ChipStack / Jasper skill**、**Synopsys Formal Advisor**：SVA 与 FPV 用，不替代仿真闭环。

Intel Quartus 没有官方 AI assistant。Quartus 路径若要用 agent，目前公开可指认的是 SynthPilot 一类第三方 MCP，且同步构建有卡死 IDE 的失败模式（见第七节）。

## 六、2026 可落地工作流

对准现有工具，不换仿真器、不换 FPGA 厂商。Vivado 与 Quartus 都走 MCP 驾驶；仿真跟已经在用的 Questa 或 VCS；测试语言优先 cocotb，SV / UVM 留给已有环境，不让 agent 从零生成。

**步骤 1。人持有 golden 与 spec。** `golden.py` 或等价 C 模型入库、评审、冻结。禁止同一模型同时写 RTL 和 checker。

**步骤 2。日间 CI（快闭环）。** `verilator lint` → `pytest-cocotb` 对冻结 golden → coverage。失败只改 RTL，回喂 succinct 日志，n≤5。覆盖下降则 rollback。这一步对应 AutoChip / GoGoTB，不碰厂商大仿真器授权。

**步骤 3。夜间回归。** Questa 或 VCS：约束随机 + 覆盖合并。残差 bin 再让 agent 定向补测（LLM4DV / GoGoTB 的用法）。补测失败不得改 golden。

**步骤 4。协议与 CSR。** SVA 从 spec 起草 → 人审 → 有界 FPV。AgentDV 说明：没有 CSR / RAL 接地，agent 覆盖环境会直接为 0。

**步骤 5。综合与实现。** 经 MCP 调 Vivado 或 Quartus。Agent 读 WNS、CDC 报告，只建议 XDC 和策略。禁止自动 waiver。禁止把对话里的「时序已修」写成结论。

**步骤 6。Bitstream 门（必须同时满足）。**

- golden 用例通过；**并且**
- 功能覆盖达到计划；**并且**
- WNS ≥ 0（post-impl）；**并且**
- CDC 干净（无未审 waiver）；**并且**
- 若走 HLS：COSIM 过 **且** 上板过。CSIM 过或综合过单独都不开门。

**步骤 7。Skill 装入仓库。** 先写入第五节六条；有 SynthPilot 再叠加 oh-my-fpga 13 条。AMD 文档 MCP 作为只读知识源，始终开着。

Questa 还是 VCS：不为 AI 切换。Siemens Agentic Toolkit 已在 2026-02 进入 EA；Synopsys 长跑 DV agent 新闻稿写 2026 H2 供货。哪边能拿到 EA 用哪边。cocotb 两边都能挂。

## 七、失败模式与证据边界

### 失败模式（按危害排序）

1. **综合过但算错。** FinHardBench 功能正确 19–61%。这是主风险。门禁必须卡 golden 与覆盖，不能卡「bitstream 能生成」。
2. **TB 共谋。** Agent 改 checker 或放宽断言，让错误用例变绿。所以 golden 冻结、同一模型不得双写。
3. **幻觉 Tcl / 过时 Vivado 命令被写成「时序已修」。** 必须交 post-impl 报告。文档 MCP 只能降低这个风险，不能消灭它。
4. **HLS：CSIM 过、上板挂。** COSIM 和上板是两道独立门。
5. **一次性 UVM。** 环境起不来（UVM² 复现 0%），时间耗在修 TB 而不是修 RTL。
6. **Quartus 同步构建卡死 IDE。** 第三方 MCP 驱 Quartus 时，构建必须异步、可杀进程，不要堵在 GUI 会话里。

### 证据边界（汇报时不要写硬）

- GoGoTB、AgentDV、FPGAgent 是 2026-07 / 08 预印本，不是已评审定论。
- VerilogCoder 94.2% 是 VerilogEval-Human v2 作者报，与交易 IP、与 bitstream 签核无推导关系。
- MCP / skill 仓库公开星数约 0–109，只说明早期，不说明不可用，也不说明已验证。
- SynthPilot「900+ 工程师」是官网宣传。
- AMD MCP 文档搜索已进 2026.1，执行层 EA / GA 边界公开文档不完全清楚。
- 厂商 50× / 40× / 10× 是新闻稿或 EA 环境，不能写入项目计划作分母。
- 不存在 Questa One SimAI、不存在 Synopsys AgentAR、Quartus 无官方 AI assistant。这三项若出现在他人口径里，按名称错误处理，不要跟写。
